## ① 业务场景

> "商品支持多规格，用户选完颜色 + 尺码才能加购。
> 运营要按规格查库存，财务要按'颜色'维度出销售报表，
> 采购单要能指向具体某个规格，商品详情页要展示可选规格组合。"

四个需求，来自三个部门，指向同一个模型。

## ③ 模型

### 3.1 五个概念的职责

| 概念 | 回答什么问题 | 谁在用它 |
|---|---|---|
| category | 这东西属于哪个类目 | 前台导航、后台权限 |
| attr / attr_value | 有哪些规格维度、每个维度有哪些值 | 筛选器、报表分组 |
| spu | 这个商品**是什么**（标题、图文、品牌） | 详情页展示 |
| sku | 这个商品**怎么卖**（价格、条码、库存、成本） | 订单、库存、采购 |
| sku_attr_value | 某个 sku 的规格组合是什么 | 详情页规格选择器 |

一句话记法：**SPU 是"商品"，SKU 是"货品"**。所有交易、库存、成本都挂在 SKU 上。

### 3.2 DDL

```sql
create table category (
  id        bigserial primary key,
  parent_id bigint references category(id),
  name      varchar(64) not null
);

create table attr (
  id         bigserial primary key,
  name       varchar(32) not null unique,   -- 颜色 / 尺码 / 容量
  input_type varchar(16) not null default 'select'
);

create table attr_value (
  id      bigserial primary key,
  attr_id bigint not null references attr(id),
  value   varchar(64) not null,
  unique (attr_id, value)                    -- 同维度下不重复
);

create table spu (
  id          bigserial primary key,
  category_id bigint not null references category(id),
  title       varchar(255) not null,
  brand_id    bigint,
  status      smallint not null default 0,   -- 0 下架 1 上架
  created_at  timestamptz not null default now()
);

create table spu_attr (
  spu_id  bigint not null references spu(id),
  attr_id bigint not null references attr(id),
  sort    int not null default 0,
  primary key (spu_id, attr_id)
);

create table sku (
  id         bigserial primary key,
  spu_id     bigint not null references spu(id),
  sku_code   varchar(64) not null unique,    -- 对外条码
  spec_hash  char(32) not null,              -- 规格组合指纹
  price      numeric(12,2) not null,
  cost_price numeric(12,2),
  status     smallint not null default 1,    -- 0 下架 1 在售
  unique (spu_id, spec_hash)                 -- ★ 防重复规格
);

create table sku_attr_value (
  sku_id        bigint not null references sku(id) on delete cascade,
  attr_id       bigint not null references attr(id),
  attr_value_id bigint not null references attr_value(id),
  primary key (sku_id, attr_id)
);

create index idx_sav_value on sku_attr_value (attr_id, attr_value_id);
create index idx_sku_spu on sku (spu_id);
```

三条关键约束，少一条就出问题：

1. `unique (attr_id, value)` —— 防止"红"和"红色"变成两个值
2. `unique (spu_id, spec_hash)` —— 防止并发创建出重复规格
3. `primary key (sku_id, attr_id)` —— 一个 SKU 在一个维度上只能有一个值

### 3.3 SQLAlchemy 2.0 写法

`app/models/catalog.py`：

```python
from decimal import Decimal

from sqlalchemy import (
    BigInteger,
    ForeignKey,
    Index,
    Numeric,
    SmallInteger,
    String,
    UniqueConstraint,
)
from sqlalchemy.orm import Mapped, mapped_column, relationship

from app.models import Base


class Category(Base):
    __tablename__ = "category"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    parent_id: Mapped[int | None] = mapped_column(BigInteger, ForeignKey("category.id"))
    name: Mapped[str] = mapped_column(String(64), nullable=False)


class Attr(Base):
    __tablename__ = "attr"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    name: Mapped[str] = mapped_column(String(32), unique=True, nullable=False)
    input_type: Mapped[str] = mapped_column(String(16), nullable=False, default="select")


class AttrValue(Base):
    __tablename__ = "attr_value"
    __table_args__ = (UniqueConstraint("attr_id", "value", name="uq_attr_value"),)

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    attr_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("attr.id"), nullable=False)
    value: Mapped[str] = mapped_column(String(64), nullable=False)


class Spu(Base):
    __tablename__ = "spu"

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    category_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("category.id"), nullable=False)
    title: Mapped[str] = mapped_column(String(255), nullable=False)
    brand_id: Mapped[int | None] = mapped_column(BigInteger)
    status: Mapped[int] = mapped_column(SmallInteger, nullable=False, default=0)

    skus: Mapped[list["Sku"]] = relationship(back_populates="spu")
    attrs: Mapped[list["SpuAttr"]] = relationship(back_populates="spu")


class SpuAttr(Base):
    __tablename__ = "spu_attr"

    spu_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("spu.id"), primary_key=True)
    attr_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("attr.id"), primary_key=True)
    sort: Mapped[int] = mapped_column(nullable=False, default=0)

    spu: Mapped[Spu] = relationship(back_populates="attrs")


class Sku(Base):
    __tablename__ = "sku"
    __table_args__ = (UniqueConstraint("spu_id", "spec_hash", name="uq_sku_spec"),)

    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    spu_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("spu.id"), nullable=False)
    sku_code: Mapped[str] = mapped_column(String(64), unique=True, nullable=False)
    spec_hash: Mapped[str] = mapped_column(String(32), nullable=False)
    price: Mapped[Decimal] = mapped_column(Numeric(12, 2), nullable=False)
    cost_price: Mapped[Decimal | None] = mapped_column(Numeric(12, 2))
    status: Mapped[int] = mapped_column(SmallInteger, nullable=False, default=1)

    spu: Mapped[Spu] = relationship(back_populates="skus")
    attr_values: Mapped[list["SkuAttrValue"]] = relationship(back_populates="sku")


class SkuAttrValue(Base):
    __tablename__ = "sku_attr_value"
    __table_args__ = (Index("idx_sav_value", "attr_id", "attr_value_id"),)

    sku_id: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("sku.id", ondelete="CASCADE"), primary_key=True
    )
    attr_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("attr.id"), primary_key=True)
    attr_value_id: Mapped[int] = mapped_column(
        BigInteger, ForeignKey("attr_value.id"), nullable=False
    )

    sku: Mapped[Sku] = relationship(back_populates="attr_values")
```

写完记得在 `app/models/__init__.py` 里导入，否则 Alembic 采集不到：

```python
from app.models.catalog import Attr, AttrValue, Category, Sku, SkuAttrValue, Spu, SpuAttr  # noqa: F401
```

### 3.4 spec_hash：防止重复规格

规格组合需要唯一。做法是把 `(attr_id, attr_value_id)` 排序后哈希：

```python
import hashlib


def build_spec_hash(pairs: list[tuple[int, int]]) -> str:
    """pairs: [(attr_id, attr_value_id), ...]"""
    raw = "|".join(f"{a}:{v}" for a, v in sorted(pairs))
    return hashlib.md5(raw.encode()).hexdigest()
```

为什么必须排序：`颜色=红, 尺码=M` 和 `尺码=M, 颜色=红` 是同一个规格，
不排序会算出两个 hash，唯一约束失效。

## ④ 为什么不能用 JSON 存规格

AI 默认会这么写：

```python
specs: Mapped[dict] = mapped_column(JSON)   # {"颜色": "红", "尺码": "M"}
```

能跑通详情页。但对一下四个需求的实现成本：

| 需求 | JSON 方案 | 拆表方案 |
|---|---|---|
| 按规格查库存 | 全表扫 + 应用层过滤 | 走索引，毫秒级 |
| 采购单指向具体规格 | 只能存字符串，无外键 | FK 到 `sku_id`，强一致 |
| 报表按颜色聚合 | **无法实现** | 一条 SQL |
| 属性改名 | 洗全表数据 | 改 `attr_value.value` 一行 |
| 防重复规格 | 无约束 | `spec_hash` 唯一索引 |
| 规格筛选器 | 要遍历所有商品解析 JSON | `select distinct` 一次 |

**判断标准**：只要这个字段会被**查询、聚合、引用**，它就必须是列，不能是 JSON。
JSON 只适合"纯展示、永不被检索"的冗余字段（比如埋点扩展信息）。

## ⑤ 验证：建模对不对，就看 SQL 写不写得出来

这是检验的唯一标准。按"颜色"维度聚合销量：

```sql
select av.value              as color,
       sum(oi.qty)           as qty,
       sum(oi.qty * oi.price) as amount
from order_item oi
join sku s              on s.id = oi.sku_id
join sku_attr_value sav on sav.sku_id = s.id
join attr a             on a.id = sav.attr_id and a.name = '颜色'
join attr_value av      on av.id = sav.attr_value_id
group by av.value
order by amount desc;
```

另一个必测查询 —— 详情页规格选择器：

```sql
select a.id as attr_id, a.name as attr_name, av.id as value_id, av.value
from spu_attr sa
join attr a        on a.id = sa.attr_id
join sku_attr_value sav on sav.attr_id = a.id
join sku s         on s.id = sav.sku_id and s.spu_id = :spu_id and s.status = 1
join attr_value av on av.id = sav.attr_value_id
group by a.id, a.name, av.id, av.value, sa.sort
order by sa.sort, av.id;
```

如果这两条 SQL 你写不出来，模型就是错的。

> 补充认知：SQLAlchemy 不是用来"逃离 SQL"的。
> ERP 报表几乎全是原生 SQL，ORM 只负责写入和单条读取。
> 这个认知在 M4 会反复出现。

## ⑦ 验收清单

| # | 检查项 | 不满足的后果 |
|---|---|---|
| 1 | 价格在 `sku` 上，不在 `spu` 上 | 同款不同规格价格无法表达 |
| 2 | 属性值有独立 ID，SKU 引用 ID | 改名要洗数据，报表会裂 |
| 3 | `sku_attr_value` 有 `(attr_id, attr_value_id)` 索引 | 报表全表扫 |
| 4 | 有 `spec_hash` 唯一约束 | 并发下产生重复规格 |
| 5 | `spec_hash` 计算时排序了 | 顺序不同算两个 hash |
| 6 | SKU 下架用 `status`，不删除 | 历史订单外键断裂 |
| 7 | 金额用 `Numeric`，不用 `Float` | 出现 0.30000000000004 |
| 8 | 时间用 `timestamptz`，不用 `timestamp` | 跨时区错乱 |

### AI 在这个环节几乎一定会犯的错

| 错误 | 为什么必然发生 | 你要问它的问题 |
|---|---|---|
| 用 JSON 存 specs | 它优化"代码短"，不优化"可查询" | "运营要按颜色出报表，你的 SQL 怎么写？" |
| 属性值存字符串 | 它把属性当标签，不当实体 | "运营把'红'改成'正红'，历史订单报表还对吗？" |
| 价格放 SPU | 它以为一个商品一个价 | "同款 T 恤 S 码 99、XXL 码 119，怎么存？" |
| 没有 spec_hash | 它不知道有并发 | "两个人同时给同一个 SPU 加规格，会怎样？" |
| 直接 `session.delete(sku)` | 它把删除当正常操作 | "删了之后历史订单的 sku_id 指向谁？" |
| 用 `float` 存价格 | Python 默认数值类型 | "0.1 + 0.2 在 float 里等于多少？" |

## ⑧ 破坏性验证

三个实验，每个都对应一个失败模式：

### 实验 1：并发建 SKU 会不会重复

用 10 个协程同时创建同一个规格组合。正确结果：1 个成功，9 个抛 `IntegrityError`。
错误结果：创建出 10 条记录，或者静默成功。

```python
async def create_one(shash: str):
    async with SessionLocal() as s:
        s.add(Sku(spu_id=1, sku_code=uuid4().hex, spec_hash=shash, price=Decimal("99")))
        await s.commit()
```

### 实验 2：下架一个中间 SKU

把 `颜色=红, 尺码=M` 的 SKU 置为 `status=0`，然后问：

- 详情页规格选择器应该怎么渲染？
- 正确行为：**该组合置灰不可选**，而不是从列表消失（消失会让用户以为选错了）

这是前端产品问题，但答案由后端接口形状决定 —— 接口必须返回"规格矩阵 + 每个组合的可用性"，
而不是只返回"可售规格列表"。

### 实验 3：属性值改名

把 `attr_value` 里"红"改成"正红"，重新跑第 ⑤ 节的报表 SQL。

- 正确：历史订单报表跟着变成"正红"（因为引用的是 ID）
- 错误：报表里出现两个"红"

## ⑨ ADR

```markdown
# 003 商品采用 SPU/SKU 拆表 + 属性字典化

## 决策
- SPU 描述商品是什么，SKU 描述怎么卖，价格与库存挂 SKU
- 规格属性用 attr / attr_value 字典表，SKU 通过 sku_attr_value 引用 ID
- 用 (spu_id, spec_hash) 唯一约束防止并发产生重复规格

## 代价
- 详情页需要 3~5 次 join，需 Redis 缓存聚合结果（M5-04）
- 建 SKU 的业务逻辑变复杂，要做笛卡尔积 + 校验
- 属性维护需要后台功能，不能像 JSON 那样随手改

## 收益
- 库存、采购、订单、报表全部可直接 SQL 聚合
- 属性改名不影响历史数据
- ERP 可无痛接入同一套主数据
```
