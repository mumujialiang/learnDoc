# 003 商品采用 SPU/SKU 拆表 + 属性字典化

## 状态

已采纳

## 背景

商品需要支持多规格售卖，同时运营要按规格维度出报表、采购要指向具体规格、
ERP 要管理到规格级库存。早期用 JSON 字段存规格可以最快跑通详情页，
但无法支撑聚合查询与外键引用。

## 决策

- SPU 描述商品是什么（标题、类目、品牌、图文）
- SKU 描述商品怎么卖（价格、成本、条码、库存），所有交易挂 SKU
- 规格属性用 `attr` / `attr_value` 字典表，SKU 通过 `sku_attr_value` 引用属性值 ID
- 用 `(spu_id, spec_hash)` 唯一约束防止并发产生重复规格
- SKU 只下架不物理删除

## 代价

- 详情页需要 3~5 次 join，必须加 Redis 缓存
- 建 SKU 需实现笛卡尔积生成 + 缺省组合校验，业务代码量增加
- 属性维护需要独立后台功能，不能像 JSON 那样随手改

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| JSON 字段存 specs | 无法按规格聚合，无外键，报表与采购全部失效 |
| 属性和值都存字符串 | 改名需洗全表，同义值会分裂 |
| 单表商品 + 变体行 | 商品信息与销售信息耦合，类目扩展困难 |

## 收益

- 库存、采购、订单、报表全部可直接 SQL 聚合
- 属性改名不影响历史数据（引用 ID）
- 商城与 ERP 共用同一套主数据模型
