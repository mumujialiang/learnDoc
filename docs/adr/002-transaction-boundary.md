# 002 事务边界由依赖层统一持有

## 状态

已采纳

## 背景

若每个 service 方法自行 `commit()`，一个下单请求会拆成订单事务与库存事务两个独立提交，
库存扣减失败时订单已落库，产生超卖且系统自身无法察觉。

## 决策

- 一个 HTTP 请求 = 一个事务
- `get_db` 依赖在 `yield` 后的 `else` 分支提交，异常分支回滚
- 路由与 service 只调用 `flush()`，禁止 `commit()`
- 事务内禁止任何外部 IO（HTTP、MQ、短信）

## 代价

- service 不能被单独作为"独立事务单元"复用，批量任务需自管事务
- 需要 review 纪律拦截随意写的 `commit()`
- 一次性处理超大数据集时事务会变长，需要拆批

## 备选方案

| 方案 | 为什么不选 |
|---|---|
| service 内部各自 commit | 部分提交，数据不一致 |
| 路由内显式 `async with session.begin()` | 与依赖注入的事务重复，易出现嵌套错误 |
| 只在需要时手动开事务 | 忘记开事务的概率远高于忘记提交 |

## 收益

- 不存在部分提交
- 事务范围只有一处定义，可审计
- 路由代码不需要关心事务
